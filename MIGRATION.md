# VitePress → Astro + Starlight Migration

This document records how the site moved from VitePress to Astro + Starlight
(branch `migrate/astro-starlight`) and the decisions that future contributors
must respect.

## What stayed the same

- **Markdown is the source of truth.** All content lives in
  `src/content/docs/` as plain `.md` files with YAML frontmatter. No MDX, no
  CMS, no JSON content stores.
- **Routes and anchors are unchanged.** Every old URL still resolves, including
  the exact heading fragment IDs (the build re-implements VitePress' slugify
  algorithm in `src/utils/slugify.mjs` + `src/plugins/rehype-heading-ids.mjs`).
- **Canonical URLs** are preserved per page through frontmatter `head`
  overrides (section indexes keep their trailing slash).
- **Sidebar structure** (emoji labels, collapsed groups, anchor deep-links) is
  maintained in `src/config/sidebar.mjs`.
- **Store badges** (`🌱` F-Droid / `▶️` Play Store links) are still
  transformed at build time, now by `src/plugins/rehype-store-links.mjs`.
- **LLM/Markdown exports** (`llms.txt`, `llms-full.txt`, per-page `.md`) are
  generated by `src/integrations/llms-export.mjs`.
- **SEO**: JSON-LD graph, Open Graph, canonicals, `sitemap.xml`,
  `robots.txt`, `_headers` are all preserved (see `src/overrides/Head.astro`
  and `src/integrations/sitemap.mjs`).
- **Search** is local (Pagefind, built into Starlight).
- **Edit links** and **last-updated** dates still derive from GitHub/git.

## What changed

| Area | Before (VitePress) | After (Astro + Starlight) |
| :--- | :--- | :--- |
| Framework | VitePress | Astro 7 + Starlight |
| Content path | `docs/` | `src/content/docs/` |
| Assets | `docs/public/` | `public/` |
| Config | `docs/.vitepress/config.mjs` | `astro.config.mjs` + `src/config/sidebar.mjs` |
| Theme | custom Vue theme | Starlight + overrides in `src/overrides/` |
| Search | VitePress local search | Pagefind |
| Containers | `::: tip/warning/danger/info` | Normalized to Starlight asides at content load time |
| Sitemap | hand-written `sitemap.xml` | Generated by `src/integrations/sitemap.mjs` |
| PWA | `vitepress-plugin-pwa` | Custom integration wrapping `vite-plugin-pwa` |

## Offline behavior (deliberate policy change)

The old service worker **precached every documentation page**, creating a full
offline mirror of the docs. This migration removes that on purpose:

- Static assets (hashed JS/CSS, icons, favicons, manifest) are precached.
- **Documentation HTML is never precached and never runtime-cached.**
- Offline navigation falls back to `/offline`, a dedicated page that explains
  the situation and offers **Retry** (and auto-retries when the network
  returns).
- The site remains fundamentally network-dependent; caching exists for
  performance and resilience, not for offline reading.

Do not reintroduce HTML precaching without an explicit decision.

## Validation

`scripts/validate.mjs` checks the built site against the archived VitePress
baseline (`/home/user/baseline` when present):

- every old URL resolves in `dist/`
- all 1080+ baseline heading IDs survive
- canonicals and `<title>`s match page for page
- `sitemap.xml` URL set is identical
- LLM exports exist and all their links resolve
- `sw.js` precaches the offline page but **no documentation HTML**
- Pagefind index is present

Run it with `npm run validate`. Without the baseline archive it degrades to
self-contained checks (routes, exports, service worker, search index, SEO).
